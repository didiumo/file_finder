# file_finder 设计文档

> 局域网文件索引 / 搜索 / 收藏整理工具的设计说明。配套代码见 `server/` 与 `client/`。

---

## 1. 背景与目标

用户需要管理一个局域网共享目录（`\\Desktop-lt9c0uj\d\MJRelease\SimulatorApp_Data\mj`，
约 106k 文件 / 204GB，以图片为主）中的文件：快速检索、预览、把「要保留的文件」以收藏方式
标记出来，最终将收藏内容归集到本地一处，其余全部清理。

核心约束：

- **效率优先**：107k 文件级别的浏览、搜索、滚动都必须毫秒级响应，不能卡顿。
- **收藏即保留清单**：收藏是唯一保留依据，其余内容在确认后被删除。
- **安全**：删除前必须预览计划；收藏文件 / 收藏目录子树在任何情况下都不得被删除。
- 复用框架 v2 插件（db_v2 / response_v2 / task / audit_v2），验证其多线程并发能力。

## 2. 总体架构

```
┌───────────────────────── py-lite-server 框架 ─────────────────────────┐
│  uvicorn (FastAPI)                                                    │
│   ├── /api/file_finder/*     file_finder REST API（api_router）        │
│   ├── /ui/file_finder/       Vue3 构建产物（dist/，SPA history 路由）    │
│   └── 插件：db_v2(WAL+读写池)  response_v2(JSON协商)  task(SSE)  audit_v2 │
└───────────────────────────────────────────────────────────────────────┘
        │                          ▲
        │ 扫描（8 线程并发遍历）      │ 查询 / 删除 / 收藏 / 预览
        ▼                          │
┌───────────────────────────────────────────────┐
│ SQLite: file_finder.db（WAL）                  │
│  roots / files(+覆盖索引) / favorites / files_fts │
│  缩略图缓存: data/thumbs/*.webp                 │
│  收集目标:  data/collected/                     │
└───────────────────────────────────────────────┘
```

前端为独立 Vue 3 + Vite 工程（`client/`），构建产物直接输出到 `dist/`，
由框架 `ui_service` 挂载，与后端同源部署。

## 2b. 文件系统浏览模块（fs，2026-09-19 新增）

「文件系统」页签提供类 Windows 资源管理器的按需目录浏览，与索引扫描解耦：

- **实时读盘**：`GET /api/file_finder/fs/list?path=<abs>&page=&page_size=` 直接 `os.scandir`
  当前目录（目录优先 + 名称排序，键集分页），**不触发、不依赖全量扫描**——目录是“多出来的内容”，
  扫描索引只服务搜索 / 预览 / 收藏。
- **路径护栏**：仅允许浏览已启用扫描根（`roots.enabled=1`）的 realpath 前缀内路径，越界返回 400。
- **索引关联**：每项尝试按 `(root_id, rel_path)` 关联索引行，命中则携带 `files.id`
  （缩略图 / 预览 / 收藏可用）；未索引的新文件 `id=null`、`indexed=false`，预览面板提示「未索引」。
- **排除目录**：与扫描器共用 `exclude_names`（默认 `metadata`），记录数据目录浏览时不可见、不可进入。
- **面包屑 + 进入搜索**：前端面包屑逐级跳转；「在此目录搜索」携带 `(root_id, prefix)` 进入搜索页签，
  搜索接口以 `rel_path = prefix OR LIKE prefix/%` 限定目录子树，实现 everything 的“进入文件夹搜索”。
- **搜索竞态保护**：列表重建（`listKey` 代次）后，旧页请求的响应一律丢弃（`gen !== listKey`），
  避免快速连续搜索 / 切换视图时旧 total 覆盖新结果。

## 3. 数据模型

### roots —— 扫描根

| 字段 | 说明 |
|---|---|
| path | 网络共享路径（UNIQUE） |
| display_name / enabled | 展示名 / 是否参与搜索 |
| last_scan_at / last_scan_count / last_scan_elapsed | 最近一次扫描记录 |

### files —— 文件索引（107k 行量级）

| 字段 | 说明 |
|---|---|
| root_id + rel_path | 唯一键（UNIQUE），rel_path 为根内相对路径（`/` 分隔） |
| name / parent_dir / ext | 文件名 / 父目录 / 小写扩展名 |
| size / mtime / is_dir | 大小 / 修改时间 / 是否目录 |
| indexed_at | 索引时间 |

覆盖索引（支撑浏览排序与过滤，避免全表排序）：

```
idx_files_name_dir  (name, is_dir, id)
idx_files_size_dir  (size, is_dir, id)
idx_files_mtime_dir (mtime, is_dir, id)
idx_files_root / parent / ext / rel
```

### favorites —— 收藏快照（独立于 files）

收藏记录 `root_id + rel_path` 的快照字段（name/size/mtime/ext）。**设计要点**：
收藏不依赖 files 行存在 —— 磁盘文件被外部删除后收藏记录仍在，列表中以
`exists_now=false` 标记「丢失」；只有「在本工具内显式删除文件」才会同步删除收藏
（显式删除 = 明确放弃保留）。

### files_fts —— FTS5 trigram 全文索引（外部内容表）

```sql
CREATE VIRTUAL TABLE files_fts USING fts5(
    name, rel_path,
    tokenize = 'trigram',
    content = 'files', content_rowid = 'id');
```

- trigram：任意子串匹配、大小写不敏感、**≥3 字符**生效；中文也按字符三元组切分。
- 外部内容表 + `AFTER INSERT/DELETE/UPDATE` 触发器与 files 表保持事务一致。
- 自愈机制（见 §6）：启动时行数一致 + `MATCH` 探活，异常则 DROP 重建 + 回填（1.1s/107k）。

## 4. 索引引擎（扫描）

### 并发模型

```
遍历阶段（8 工作线程）             写库阶段（事件循环内）
┌──────────────────────┐  队列   ┌──────────────────────┐
│ scandir + stat 并行   │ ──────▶ │ 异步消费者            │
│ 目录队列 + 记录队列    │ 2000条/批│ execute_many 批量写入  │
└──────────────────────┘        └──────────────────────┘
```

- 工作线程共享目录队列，`os.scandir` 单次遍历直接产出记录（避免逐文件 stat 两次）；
  跳过符号链接（防环）。
- 生产者消费者解耦：遍历线程不碰 DB；消费者在事件循环内每批 2000 条
  `db_v2.execute_many` 落库（WAL 模式），每处理 500 条主动 `await sleep(0)` 让出事件循环，
  保证扫描期间 HTTP 接口不被饿死。
- **增量模式**：`_load_existing` 载入 `rel_path → (id,size,mtime,is_dir)`，
  遍历时对比：新增 → INSERT；size/mtime 变化 → UPDATE；磁盘已不存在 → 按 id 分批 DELETE。
- **全量模式**：先 `DELETE FROM files WHERE root_id=?`（触发器同步清 FTS），再全量写入。

### 已知坑与对策（实录）

| 现象 | 根因 | 对策 |
|---|---|---|
| 扫描期间全部 API 超时 | 消费者 `queue.get(timeout)` 阻塞事件循环 | 改 `get_nowait()` + `sleep(0.01)` 轮询 |
| `asyncio.to_thread(...).done()` 报错 | Future 使用方式错误 | 改 `create_task` 持有引用 |
| FTS 触发器 `incomplete input` | schema 按 `;` split 切断触发器语句 | 改为 `_SCHEMA_STATEMENTS` 语句列表逐条执行 |
| 全量扫描后 FTS MATCH 全 0 / malformed | 先 DELETE files 再回填时序下索引损坏（复现见 `check_fts6.py`） | 启动探活 + 自动 DROP 重建回填；离线重建见 `tools/rebuild_fts.py` |
| 深层目录 rel_path 丢失祖先前缀（`<uuid>/metadata/2022/x.json` 被记成 `2022/x.json`），大量文件碰撞覆盖、行数塌缩、缩略图全部 404 | 遍历 worker 子目录入队只传目录名 `e.name`，两层以上路径丢失祖先 | 子目录入队改为携带完整相对路径 `f"{rel_dir}/{e.name}"`（`indexer_logic._parallel_walk`） |
| 全量重扫后行数没变（疑似没写入） | `INSERT OR REPLACE` + `UNIQUE(root_id, rel_path)` 使碰撞路径互相覆盖 | 路径 bug 修复后不再碰撞；用日志核对 DELETE/INSERT rowcount |

### 排除目录（记录数据不索引）

用户明确要求「配置文件里面的记录数据可以完全不用管」。扫描时按目录名排除，
整个子树不索引、不显示、不参与搜索：

```yaml
# server/config.yaml
exclude_names:
  - metadata
```

遍历 worker 遇 `e.name in exclude_names` 直接 `continue`（不入队、不记录目录自身）。
默认排除 `metadata`，可在配置中增删。离线重置/重建工具：`tools/cleanup_reset.py`
（移除指定根 + 重建 FTS，需在服务停止时运行）。

## 5. 搜索与分页（性能核心）

### FTS 路径与回退

- `q` ≥ 3 字符：`f.id IN (SELECT rowid FROM files_fts WHERE files_fts MATCH '"<q>"')`
  （引号转义防注入），trigram 任意子串匹配，107k 行命中查询 **20ms**。
- `q` 1~2 字符：回退 `name/rel_path LIKE %q%`（转义通配符，`ESCAPE '\'`），实测 79ms。
- 过滤条件（root / ext / size 区间 / 时间区间 / 仅收藏 / 是否含目录）拼入 WHERE，
  全部走覆盖索引。

### 游标分页（深翻页 O(页大小)）

`OFFSET` 深翻页要扫描并丢弃前 N 页（107k 行 name 排序下 page=100 代价高），
改为**键集分页**：响应携带 `next_cursor = {after_name|size|mtime, after_id}`，
下一页用 `(sort_col > ? OR (sort_col = ? AND id > ?))` 定位。前端按页缓存游标，
顺序滚动时每页只取 300 行。实测游标翻页 **58ms/页**，与页号无关。

### 实测性能（107,501 行，本机直连 127.0.0.1）

| 场景 | 耗时 |
|---|---|
| FTS 搜索 q=config | 20ms |
| 短词 q=mj（LIKE） | 79ms |
| 浏览 name/size/mtime 第 1 页 | 32~48ms |
| ext=png 过滤 | 92ms |
| 收藏列表 | 2ms |
| 游标深翻页（20 页均值） | 58ms/页 |
| 10 并发 size desc | 全完成 152ms |

> 注意：本机压测请用 `127.0.0.1` 而非 `localhost` —— Windows 上 Python 解析
> `localhost` 先试 IPv6 `::1`（服务仅监听 IPv4），失败回退会白白增加 ~2s。

## 6. FTS 自愈

真实库曾出现「行数一致但索引损坏」（MATCH 全 0、integrity-check 报 malformed）。
启动 `_sync_fts_backfill` 逻辑：

1. 比较 `COUNT(files_fts)` 与 `COUNT(files)`，不一致 → 重建。
2. 一致 → 用 `MATCH 'json'` 探活（一个必然命中词），异常 → 重建。
3. 重建 = DROP 触发器×3 → DROP 虚表 → CREATE VIRTUAL TABLE + 触发器×3 → INSERT SELECT 回填。

重建在 107k 行上实测 1.1s，可在启动时无感完成。

## 7. 预览能力矩阵

| 类型 | 实现 | 细节 |
|---|---|---|
| 文本（txt/md/json/log/代码等） | 服务端读前 256KB | BOM→UTF-8→GBK 探测；响应头 `X-Preview-Encoding` / `X-Preview-Truncated`；前端 marked 渲染 MD |
| 图片 | 原图直出 / 缩略图 | 缩略图用 Pillow 生成 WebP 缓存到 `data/thumbs/`（size 参数 96/160/240/256） |
| 视频 | HTTP Range 206 | 原生 `<video>` 流式播放（已验证 Range 请求） |
| 压缩包 / DLL / 程序库 | **不预览** | 返回 415 + 前端「该类型暂不支持预览」+ 下载按钮 |

## 8. 搜索能力矩阵（2026-09-19 更新）

| 能力 | 实现 | 说明 |
|---|---|---|
| 文件名 / 路径子串 | FTS5 trigram（≥3 字符）或 LIKE（短词） | 大小写不敏感 |
| 文件夹搜索 | `include_dirs` 默认开启 | 目录与文件同权出现在结果中（everything 风格） |
| 正则匹配 | `regex=1`：Python `re.IGNORECASE` 过滤 name / rel_path | 候选全量查库 + 内存分页；无效正则返回 400 |
| 目录范围搜索 | `prefix=<rel_path>`：目录自身 + 子树 | 由「在此目录搜索」一键进入 |
| 扩展名 / 大小 / 时间 / 仅收藏 | WHERE 条件组合 | `ext=__dirs__` 特殊值 = 只显示目录（搜索 `is_dir=1`，收藏 `ext=''`） |
| 类型过滤 | 扩展名多值 IN；收藏页同样支持 | 📁 文件夹选项在搜索/收藏页通用 |
| 排序与分页 | name/ext/size/mtime/rel_path + 游标；正则模式走 OFFSET | 深翻页 O(页大小)；表格视图点击列头排序 |
| 表格视图 | 列标题 + 点击排序 + 列宽拖拽 | 列宽存 localStorage；行与表头 flex 同源（`colStyle`） |

## 9. 整理收集流水线（collection）

```
plan（只读）──▶ 统计：收藏总大小(待复制) / 其余总大小(待删除) / 可释放空间
                返回各根明细，不产生任何副作用
run（confirm=true 才执行）
  1. 对每个根：将收藏文件复制到 data/collected/<root>/<rel_path>
     （父目录自动创建；已存在同名则跳过）
  2. 删除收藏之外的其余文件与目录：
     - 收藏文件本身豁免；收藏目录的整个子树豁免（按 realpath 前缀判定，防越界）
     - 并行删除文件（线程池），空目录自底向上移除；空根目录可选移除
  3. 执行完成后，对受影响的根自动触发增量重扫，恢复索引与磁盘一致
```

安全设计：

- 删除前必须经 `plan` 预览数字，`run` 需要 `confirm=true`，前端弹窗二次确认。
- 路径拼接全部 `realpath` 归一化后做前缀校验，杜绝 `..` 逃逸。
- 显式删除文件会同时删除对应收藏记录 —— 被删文件不可能再被收藏豁免。

## 9. 前端设计（client/，Vue 3 + Vite）

### 虚拟滚动（VirtualList.vue）—— 性能核心

```
视口（滚动容器）
┌────────────────────────────┐
│  bufferRows=8              │
│  ┌──────────────────────┐  │
│  │ 可视区（实际渲染）      │  │  每格 = <FileCard> 或表格行
│  └──────────────────────┘  │
│  bufferRows=8              │
└────────────────────────────┘
画布高度 = 总行数 × 行高（107k 文件 ≈ 1000 万 px）
```

- 只渲染可视区 ± 8 缓冲行内的单元格；滚动即按页 `fetch-page(pageIdx)`，
  响应 `{total, items}` 更新总数并缓存该页。
- **页缓存有界**：远离可视区的页自动释放（`keepMin/keepMax` 范围外删除），
  且总缓存页数 ≤ 16，内存占用恒定。
- 数据用**非响应式 Map** 存储 + `version` 计数触发重渲染，避免 107k 级深响应开销。
- 挂载时主动拉取第 0 页（total=0 时无可见单元格，否则首屏永远空白 —— 已修复）。

### 视图模式

`store.viewMode`：small（148×128）/ medium（216×188）/ large（316×264）网格
+ table（单列虚拟行：图标/名称/扩展名/大小/日期/路径/收藏标记/丢失标记）。
切换通过重建 VirtualList（`listKey++`）清空页缓存实现。

### 数据流

- 顶栏下方常驻「扫描根信息条」：完整网络路径 + 文件/目录数 + 上次扫描时间，
  并默认选中第一个扫描根（`init()` 自动设 `rootId`）—— 解决「不知道扫的是哪个路径」。
- 搜索框 150ms 防抖 → `store.q` → `filter-change` → 重建列表 → 第 0 页游标分页。
- 收藏：卡片 Ctrl/Alt/⌘+点击 → `favorites/toggle`；收藏页卡片显示名称/大小/日期，
  支持「清除失效收藏」。
- 预览：点击卡片 → 右侧 PreviewPanel（文本 marked / 图片 / 视频 / 不支持+下载）。
- 任务：TaskBar 通过 SSE（`/tasks/{id}/events`）接收进度，3s 轮询兜底。

### 已知边界

- 大图视图下所有视图按钮图标相同（grid），仅 title 区分 —— 可用不同图标优化。
- 双屏/窗口缩放时 ResizeObserver 会重算列数与行高。

## 11. 限制与后续

- 单库单实例：不支持多进程并发写同一 DB（WAL 已缓解读写冲突）。
- trigram 对 ≤2 字符词不生效（回退 LIKE，中文 2 字词命中多时偏慢）。
- 视频预览依赖浏览器解码能力；超大视频建议继续用 Range 拖动播放。
- 收藏整理目前为「复制后删除」模式；如需「移动」，可在 collect 选项扩展。
